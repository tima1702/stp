# Теоретическая часть

## 1. Интеграция LLM в процесс разработки

**Интегрированная среда разработки (IDE)** с поддержкой LLM представляет собой новый этап эволюции инструментов программирования. Такая интеграция позволяет получать помощь ИИ непосредственно в процессе написания кода.

### Основные возможности LLM в IDE:

- **Code Generation**: генерация кода по описанию
- **Code Completion**: автодополнение кода
- **Code Refactoring**: улучшение существующего кода
- **Documentation**: автогенерация документации
- **Testing**: создание unit-тестов
- **Code Review**: анализ и предложения по улучшению
- **Bug Detection**: поиск потенциальных ошибок

## 2. Архитектуры интеграции

#### Плагинная архитектура

- **Плагины**: расширения, добавляющие функциональность LLM в существующие IDE
- **API взаимодействие**: плагин общается с локальным сервером Ollama через REST API
- **Асинхронность**: запросы к модели выполняются в фоновом режиме

### Встроенная интеграция

- **Native support**: редакторы с изначальной поддержкой LLM (Cursor, Zed)
- **Seamless experience**: более плавное взаимодействие с моделью
- **Оптимизация**: лучшая производительность за счёт нативной интеграции

## 3. Типы помощников ИИ в разработке

### Code Assistants (Помощники кода)

- **GitHub Copilot**: облачный сервис от Microsoft/GitHub
- **TabNine**: гибридный подход (локальные и облачные модели)
- **CodeWhisperer**: сервис от Amazon
- **Codeium**: бесплатная альтернатива Copilot

### Local AI Assistants (Локальные помощники)

- **Ollama + плагины**: максимальная приватность
- **LocalAI**: альтернатива OpenAI API
- **LM Studio**: GUI для локальных моделей
- **GPT4All**: локальная платформа для LLM

## 4. Протоколы взаимодействия

### Language Server Protocol (LSP)

**LSP** — протокол для обеспечения функций языкового сервера в различных редакторах:

- Стандартизация взаимодействия между IDE и языковыми сервисами
- Поддержка автодополнения, диагностики, форматирования
- Возможность интеграции LLM через LSP

### REST API Ollama

Ollama предоставляет HTTP API для взаимодействия:

```
GET /api/tags          # Список доступных моделей
POST /api/generate     # Генерация текста
POST /api/chat         # Чат с моделью
POST /api/embeddings   # Получение эмбеддингов
```

## 5. Обзор популярных плагинов

### Continue (VS Code)

- **Open-source** плагин для VS Code
- Поддержка множества провайдеров (OpenAI, Ollama, Anthropic)
- Функции: автодополнение, чат, рефакторинг
- Конфигурация через JSON-файл

### DevoxxGenie (JetBrains)

- Плагин для всех IDE JetBrains (IDEA, PyCharm, WebStorm)
- Интеграция с Ollama из коробки
- Поддержка контекста проекта
- Встроенный чат и генерация кода

### Codeium

- Бесплатная альтернатива GitHub Copilot
- Поддержка 70+ языков программирования
- Доступен для большинства редакторов
- Облачный и локальный режимы работы

## 6. Контекст и prompt engineering в IDE

### Типы контекста:

1. **Файловый контекст**: текущий открытый файл
2. **Проектный контекст**: структура проекта, зависимости
3. **Исторический контекст**: предыдущие изменения и коммиты
4. **Языковой контекст**: синтаксис и семантика языка программирования

### Оптимизация промптов:

- **Инкрементальные запросы**: постепенное уточнение задачи
- **Контекстные промпты**: включение релевантного кода
- **Структурированные запросы**: четкое описание ожидаемого результата

## 7. Метрики оценки эффективности

### Качественные метрики:

- **Правильность кода**: синтаксическая и логическая корректность
- **Читаемость**: качество комментариев и структуры
- **Соответствие стилю**: следование принятым конвенциям

### Количественные метрики:

- **Время генерации**: скорость получения ответа от модели
- **Tokens per second**: производительность модели
- **Acceptance rate**: процент принятых предложений
- **Edit distance**: количество необходимых правок

## 8. Лучшие практики интеграции

### Настройка модели:

1. **Выбор размера**: баланс между качеством и скоростью
2. **Температура генерации**: контроль случайности ответов
3. **Максимальная длина**: ограничение размера генерируемого кода
4. **Stop sequences**: правильная остановка генерации

### Workflow оптимизация:

1. **Предварительный прогрев**: загрузка модели в память
2. **Кэширование контекста**: сохранение часто используемых промптов
3. **Batch processing**: группировка запросов для эффективности
4. **Fallback стратегии**: резервные варианты при недоступности модели

## 9. Безопасность и приватность

### Локальные преимущества:

- **Полная приватность**: код не покидает локальную машину
- **Отсутствие зависимости от интернета**: работа в офлайн режиме
- **Контроль данных**: полное управление обрабатываемой информацией

### Потенциальные риски:

- **Качество генерируемого кода**: необходимость тщательной проверки
- **Bias в моделях**: предвзятость обучающих данных
- **Over-reliance**: чрезмерная зависимость от ИИ-помощника

# Задачи для выполнения (пример для IDEA + DevoxxGenie)

## 1. Подготовка окружения

- Установите **JetBrains IDEA** (Ultimate или Community).
- Установите и запустите Ollama.
- Загрузите лёгкую модель:

```
ollama pull deepseek-coder:1.3b
```

## 2. Установка и настройка плагина

1. Откройте **File → Settings → Plugins → Marketplace**.
2. Найдите плагин **DevoxxGenie** и установите его.
3. Перезапустите IDEA.
4. Откройте **Settings → Tools → DevoxxGenie → Models**.
5. Если модель не отобразилась по дефолту, тогда добавьте новую модель:
    - **Provider:** Ollama
    - **Endpoint:** http://localhost:11434
    - **Model:** deepseek-coder:1.3b
6. Сохраните настройки и убедитесь, что модель появилась в списке.

## 3. Генерация кода

- Создайте новый проект на Python.
- В файле calculator.py введите запрос через чат DevoxxGenie:
    _“Напиши Python-калькулятор, который выполняет сложение, вычитание, умножение и деление”._
- Вставьте полученный код в файл и запустите его.
- Исправьте ошибки при необходимости.

## 4. Рефакторинг кода

- В чате DevoxxGenie введите:
    _“Добавь обработку ошибок и комментарии в код калькулятора”._
- Сравните версию до и после.
## 5. Дополнительные задания (минимум 3)

Примеры:
1. Генерация React-компонента кнопки с кастомным стилем.
2. Написание SQL-запроса для выборки студентов старше 20 лет.
3. Генерация юнит-тестов для калькулятора.
## 6. Оценка работы модели

- Для каждой задачи зафиксируйте:
    - Время генерации.
    - Работоспособность кода.
    - Количество правок.
- Сделайте вывод, какие задачи модель выполнила лучше всего.
